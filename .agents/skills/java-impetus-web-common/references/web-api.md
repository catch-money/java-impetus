# Web integration reference

## Feature selection

| Feature | Package and entry point | Contract |
| --- | --- | --- |
| Logging | `io.github.jockerCN.log.AutoLog` | Annotation-only usage; aspect auto-configured when AspectJ is available |
| CORS | `io.github.jockerCN.cors.EnableCorsFilter` | Explicit import; original Spring CorsFilter |
| MVC errors | `io.github.jockerCN.exception.EnableGlobalException` | Explicit import; Result body with real HTTP errors |
| JSON HTTP mapping | `io.github.jockerCN.web.EnableJacksonConverters` | Explicit import; Jackson 3 JSON slot only |
| Date/form parameters | `io.github.jockerCN.web.binding.EnableWebBinding` | Explicit import; typed DateTimeUtils parsing and optional trimming |
| Correlation ID | `io.github.jockerCN.web.request.EnableRequestId` | Explicit import; response header + request-local MDC |

Use selected annotations on the application's configuration class. No combined enable annotation is necessary.
Boot's jackson auto-configuration already uses mapper beans in ordinary applications; EnableJacksonConverters is the library's explicit MVC JSON integration, not a second mapper mechanism.

## CORS

Prefix: `java-impetus.web.cors`.
Properties: `paths`, `allowed-origins`, `allowed-origin-patterns`, `allowed-methods`, `allowed-headers`, `exposed-headers`, `allow-credentials`, `max-age` (Duration).
Defaults: `/**`, origins/header `*`, GET/HEAD/POST/PUT/PATCH/DELETE/OPTIONS, credentials false, max-age 10h.

```yaml
java-impetus:
  web:
    cors:
      allowed-origins: ["https://app.example.com"]
      allow-credentials: true
      exposed-headers: [X-Request-Id]
      max-age: 30m
```

Do not combine the wildcard allowed-origin with credentials. To use origin patterns, clear `allowed-origins` as needed, especially its default wildcard.
Supply a CorsFilter bean to replace the helper; supply a CorsConfigurationSource bean to keep the helper with custom per-path rules.
Coordinate with Spring Security rather than assuming this filter configures authorization.

## Dynamic AutoLog

```java
@Component
public class OrderLogContent implements AutoLogContentProvider {
    @Override
    public Object content(AutoLogContext call) {
        return "order=" + call.arguments()[0]
                + ", ms=" + call.elapsed().toMillis()
                + ", succeeded=" + Objects.isNull(call.failure());
    }
}

@AutoLog(value = "find order", contentProvider = OrderLogContent.class)
public Order findOrder(String id) {
    return service.find(id);
}
```

The provider interface and context are in `io.github.jockerCN.log`.
Context fields: `target`, `method`, `arguments`, `result`, `failure`, `elapsed` (Duration).
Providers run synchronously after the method returns/throws, once per enabled invocation; return any printable object.
They are Spring Beans resolved via SpringProvider. Runtime errors during provider lookup/content rendering are logged without replacing method result/exception.
Never store call contexts or request data in singleton provider fields.

Annotation options:

- `value`: label, default empty.
- `contentProvider`: provider class; default interface means none.
- `level`: SLF4J `org.slf4j.event.Level`, default INFO.
- `logArgs`, `logResult`: default false.
- `excludeArgs`: zero-based argument indexes to omit when args enabled.
- `maxLength`: default 2048, per rendered content section; output truncation is not a limit on arbitrary object's toString work.

Logs include method, SUCCESS/FAILED and duration. Failure remains thrown unchanged.
Self-invocations/unmanaged objects do not pass through Spring AOP. Elapsed/result describe method invocation, not eventual Future or streamed completion.
Supply LogAspectController bean to replace the default aspect. The static SpringProvider follows the module's single-context convention.

## JSON HTTP mapping

Uses `tools.jackson.databind.json.JsonMapper`, with default mapping from java-impetus-jackson unless the application provides one.
`@EnableJacksonConverters` replaces the native MVC JSON slot via Spring 7's ServerBuilder.
Supports application/json and application/*+json, preserving native text, binary, resource and multipart handling.
An application JacksonJsonHttpMessageConverter bean is used when supplied.
No Gson or Jackson 2 imports; no HTTP client configuration is changed.

setSupportedMediaTypes still exists in Spring 7; declaring a type does not implement its encoding.
Keep plain/HTML/Markdown strings on native String conversion, form data on MVC binding/Form conversion, and PDF/images/octet-stream on already generated byte[]/Resource content.
XML and Atom/RSS need appropriate optional converters/dependencies or pre-generated text/resources; SSE uses native streaming response handling.
Do not make JSON a catch-all for those formats. Accept `*/*` is content negotiation and still allows JSON.
Only intentionally nonstandard JSON endpoints should opt into extra media types on a consumer converter.

## Exception fallback

GlobalExceptionController extends ResponseEntityExceptionHandler and runs at LOWEST_PRECEDENCE.
Application advice should have a higher priority, for example `@Order(0)`, with specific business exception handlers.
A GlobalExceptionController/subclass bean overrides default creation.

```java
@RestControllerAdvice
@Order(0)
public class BusinessExceptionAdvice {
    @ExceptionHandler(OrderConflictException.class)
    public ResponseEntity<Result<Void>> handle(OrderConflictException exception) {
        return ResponseEntity.status(HttpStatus.CONFLICT)
                .body(Result.with(null, 409, exception.getMessage()));
    }
}
```

Register the Advice through application component scanning or explicit import.
New types need no library registry; @ExceptionHandler accepts single or multiple exception types.
Both Spring 6 and 7 support multiple advice beans. They are tried in priority order; the first matching advice handles the exception, not every advice in succession.
Do not leave priority equal to the library's LOWEST_PRECEDENCE fallback.
Use protected MVC hooks when overriding inherited handler behavior on a replacement subclass, instead of introducing conflicting handler mappings.

MVC errors preserve native HTTP status and headers: bad input 400, missing MVC resource 404, bad method 405, unsupported media 415, upload size 413.
ResponseStatusException, ErrorResponse and annotated exception types preserve status. Unexpected exceptions and MVC return-value validation failures remain 500.
ConstraintViolationException is treated as bad input. Parameter resolver exception messages are considered public.
Response body is Result with matching `code`; error logs, not client bodies, contain internal details.
This does not implement Servlet `/error` handling, security entry points, or non-MVC asynchronous error handling.

## Date/form binding

Prefix: `java-impetus.web.binding`.
Additional patterns: `date-patterns`, `date-time-patterns`, `time-patterns`, `offset-date-time-patterns`.
Target types: LocalDate, LocalDateTime, LocalTime, OffsetDateTime. Patterns compile at configuration initialization.
Parse additional patterns and DateTimeUtils's target-specific defaults. Its existing date semantics return null for an empty string; whitespace-only and malformed dates fail parsing. Missing optional parameters remain absent. This is not a global String empty-to-null rule.
`@DateTimeFormat` on the target takes precedence through Spring's native parser, including its ISO fallback; the module's extra patterns do not apply there.

`trim-strings` defaults false. When enabled, a fresh StringTrimmerEditor per binder trims request/form strings;
Trim preserves `""` rather than converting it to null. No global `empty-to-null` setting is supplied.
Null/empty coercion belongs to user field-level converters/InitBinder or custom Jackson deserialization, not library defaults.
This does not alter JSON request bodies or serialized responses.

## Request IDs

Prefix: `java-impetus.web.request-id`.
`header-name` defaults X-Request-Id, `mdc-key` defaults requestId, `trust-incoming` defaults false.
Enable only when simple request/log correlation is wanted; it is not auth or distributed tracing.
With trust enabled, accept incoming IDs only with 1–128 alphanumeric/dot/underscore/hyphen characters; otherwise generate a UUID.

RequestIdFilter.REQUEST_ATTRIBUTE is a Servlet request attribute, not a header. It carries the same ID over request/async/error dispatch.
MDC exists inside the dispatch filter scope and is restored/removed in finally. User-created async tasks do not inherit it automatically.
CORS preflight may short-circuit before ID creation. Add the response header to CORS exposed-headers for browser access.
Override RequestIdFilter bean or named `requestIdFilterRegistration` bean for custom behavior/registration.
